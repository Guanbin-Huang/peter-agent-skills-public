# 质量不减的提速路由 v1

## 使用方式

用户要求“快一点／别那么慢／优化剪辑流程”时读本页；普通任务只在入口命中对应分支后读取该分支。目标是更早交付同质量的成品，不是更少检查、更短正文或更低码率。下面是现有流程的选择器，不新增一轮规划、审批或统一预检。

## 先选本轮要做的事，再停止无关路由

| 本轮请求 | 执行入口 | 本轮不做 |
| --- | --- | --- |
| 找回／再发既有成品 | 主 skill 的“已剪成品找回与直接交付” | 新 ASR、重剪、重建高清、无关服务器排错 |
| 逻辑已确认的日常轻剪 | `日常轻量剪辑-v1.md`；现有 `render_lightweight.py` | 重构故事、额外双 ASR、未请求字幕/B-roll/片尾 |
| 改字、版式、前三帧封面或明确短插入 | `video-quick-revision` | 重做未变正文；把插入当成总时长不变 |
| 已批准工程导出高清 | `输出成品快速路径-v1.md` 的“已确认工程” | 重做取舍、重复提速、重复已验音频转写 |
| 新片／叙事重排／真实时序问题 | 既有粗剪与相应领域流程 | 用轻剪入口跳过必要内容判断和时序验收 |
| 上传／查草稿／改平台封面 | `social-auto-upload` 的原会话与阶段恢复 | 回头重剪或重新上传未变 MP4 |

轻量、返修、找回分支优先于主文件后文的通用“四核心全流程”表述。只读命中分支及其真正需要的依赖，不继续把完整模型矩阵、ASR手册、所有包装规范加载成执行清单。用户已给出的标题、格式、倍速、逻辑和开关直接继承；领域规定的候选判断契约保持，不制造候选让模型重新确认确定值。

## 变更只使真实下游失效

| 实际变更 | 失效范围 | 必须补的质量证据 | 可复用的已验部分 |
| --- | --- | --- | --- |
| 只改平台编辑页的封面字段 | 该平台横／竖封面预览和保存回读 | 实际账号、草稿身份、两个封面槽、保存结果 | MP4、正文、音轨、已完成上传；不自动修改 MP4 前三帧 |
| 改 MP4 前三帧封面 | 封面资产及受影响编码/GOP段 | 同版编码参数/PTS/边界；最终第1/3/4帧 | 未变正文内容、音轨、字幕；平台上未提交的旧媒体需按本轮发布需求判断 |
| 改字幕字面或位置 | 对应字幕资产和画面编码段 | 真正改动页、相邻边界、字形/语义断句/避让 | 未变的原声、EDL、倍速及对应对齐证据 |
| 换容器或仅音频重编码 | 输出封装／编码验证 | 新输出解码、起止时钟、时长及对应边界/源映射 | 有证据保持的语音内容和字幕对齐；字节不同不自动触发 ASR |
| 改正文剪点、顺序或速度 | 受影响音画、字幕映射与视觉事件；重排后方区间按依赖失效 | 相应原声、切点、源相对同步和字幕 timing | 无依赖变化的源转录、字体、已选封面等；不得把旧同步 PASS 移给新时间线 |
| 换 BGM／调整混音 | 混音及新输出音频验收 | 人声完整清楚、响度/峰值、接缝、语音与视频时钟 | 有源与 EDL 依据的干净人声转录；混音波形不同不等于正文改了 |

缓存复用依据是输入、时间映射、参数与已有成功记录，不是文件名。新输出仍验收新增风险；旧的失败报告保留。存在漂移、吞字、错误 take、字幕难读或画面损坏时修根因，不降低阈值把失败改成通过。

## 快的执行方法，慢不得省的判断

1. 把连续的确定性操作交给现成脚本一次执行并逐项保存结果；只在真实选择、异常或验收汇合处回到模型。已运行到中段的工作先读取阶段状态再恢复，禁止因改一个字段重启整条链。
2. 独立封面／字幕等按实际依赖并行；唯一时间线、GUI及同账号写入串行。媒体进程按本机吞吐限流，不把代理数当编码容量。小修改不因切模型多开代理。
3. 新渲染链先用代表性短样暴露字体、画质、时钟和编码问题；同状态成功证据复用。短样通过不替代新成片的相关验收，必要的硬件解码也不因追求速度删除。
4. 内容质量先保住正确素材、完整因果和有效原话；日常版保留全正文、笑声、蓄势和反应。气口数值服从完整发音与表演，禁止用强剪或加速掩盖不清楚的取舍。
5. 技术质量守住同源音画、一次倍速、字幕可读、构图完整和目标规格。硬件编码只能在同源同样式小样通过后使用；质量失败淘汰该配置，不降低分辨率/码率来兑现未经实测的时长承诺。

复杂叙事和证据冲突按当前模型路由投入推理；用户本轮点名 Astra/xhigh 时依其要求。机械步骤仍交脚本，模型档位不代替产物验收。本页不修改全局模型配置。

## 速度怎么验收

在现有项目记录中区分请求→交付总墙钟时间、工具活动区间、用户确认等待、网络/平台等待和返工。并行工具耗时不要直接求和当墙钟；工具外空档只记未归因，不直接称“模型思考耗时”。记录失败原因和重做阶段，而非只记编码秒数。

只比较相同素材、变更范围、交付规格与质量门槛的结果；质量未通过就不计为提速成功。单次样本只能说明该样本的效果，不承诺固定“一分钟完成”。已完成的附件、网页审核、平台草稿、平台审核中和公开发布分别报告；解决入口问题不重剪媒体，未核实手机播放时不声称手机已可见。

```text

复用未变资产和有效验收，用现成脚本批量做机械步骤，只重做受影响阶段。
保护正文、笑声、完整发音、同源同步、字幕清晰和目标画质；新链路先短样。
保存阶段结果，失败只修根因；分开报告总耗时、工具活动、等待与返工。
成品验收后直接交付，不把附件回执冒充手机播放或平台发布。
```
