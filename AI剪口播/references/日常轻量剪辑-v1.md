# 日常／已确认逻辑的轻量剪辑（2026-10-03）

## 触发与优先级

用户说“日常版”“简单剪剪”“逻辑已经 OK”“按我给的逻辑剪”“只剪口播气口”时，进入 `edit_mode=lightweight-breath`，不套完整导演型粗剪。用户提供的逻辑、顺序、正文和明确参数已经确认；不要重新问一套形式、B-roll、结构或 take 方案。

所有视频都极力保留大笑和笑声。常规无内容气口的最新目标是**在最终输出时间线上尽量 ≤0.30 秒**，覆盖旧的 0.30–0.40 秒默认目标。笑声、包袱蓄势、笑后反应、有效回应和完整发音优先，不能为数值达标切掉声音。

## 最短执行链

1. **锁定正确素材**：先核对用户描述的主题、时长与开头一句；日期只帮助定位，不证明就是目标。未匹配时只问开头/场景/文件，不批量转写无关旧素材。
2. **正文与封面并行**：唯一时间线写入者只剪确认无内容的气口；封面从同一原片和用户标题独立做，不等气口 EDL 才开始选帧、排字。逻辑不改的场景，封面原片帧不依赖最终时长。只有合入成片前三帧才依赖冻结的输出时间线。
3. **优先现成快速工具**：可用且已核实的剪映剪口播/快速气口功能或已有确定性链路优先；不得凭印象声称工具能自动识别、保护笑声。声音边界不清时只核对受影响短片段，不默认两套全片 ASR、多模型投票或再次创作结构。已给标题、速度与格式直接继承，不让模型重新选择。
4. **合并一次输出**：日常版画面、声音同步 **1.1×**，只应用一次；非日常视频继承该项目速度或原来的非日常默认。字幕已有则保留和映射；用户只要求轻剪、倍速和封面时，不自动增加字幕制作、固定片尾、B-roll、人物贴片等工作。明确另有包装要求才执行。
5. **最小相关验收后交付**：核对竖屏尺寸、时长、倍速一次、同源音画、完整笑声和代表性切点，封面第1–3帧、第4帧恢复正文；复用未变化链路的有效验证。手机入口复用现有已验收的 HTTPS Web Review，不重做 App 或为单条片重新探索发布架构。新链路、漂移或吞字问题出现时才扩大相关检查，不扩大整项任务。

## 已验证的脚本入口（2026-10-03）

冻结单条竖版源片、轻剪时间线与独立封面后，使用现有脚本，不再为每条视频临时重写合成器：

```bash
python3 ~/.codex/skills/AI剪口播/scripts/render_lightweight.py \
  --source SOURCE.mp4 --timeline timeline.json --cover cover.png \
  --output NEW.mp4 --profile master
```

- `timeline.json` 使用 `fps=30`、`speed`、`sources`、`segments`、`output_frames`；速度从唯一时间线读取。输入路径、输出路径和原叙事已确认，不通过该脚本自动寻找/选择内容。
- 未传 `--captions` 时为零 ASR、无字幕资产路径；有已确认字幕时加 `--captions captions.srt --font FONT.ttf --protected-terms-file atomic-units.txt`，编码前检查重叠、越界及原子词组。不要把未请求字幕变成前置门禁。
- 自动调用 `final_product_preflight.py --mode lightweight`，同源只探测一次；省略未启用的词时间与片尾。旧全流程继续用默认 `full`，不绕审核项目的 approved 门禁。
- 新输出和旁车文件有冲突就停，不覆盖已验收版本；`.render.json` 记录预检/编码/总耗时、ASR次数和编码次数，状态 `encoded` 不等于已验收或已交付。
- 将渲染和后续确定性检查放进同一批工具执行，避免每项都等模型再决定。新成片用既有 `verify_source_timing.py --cache SOURCE_CACHE`，缓存复用原片解码，不豁免新输出；完成必要解码/元数据/封面1–3帧及第4帧检查后再发布。回滚副本若与已验收原件SHA一致，只核对恢复状态，复用原件解码证据。
- 本次实测仅针对**现成时间线与封面**：70.7秒1080×1920输出，预检约0.084秒、编码约25.874秒；渲染与实际QA活动工具时间合计约44.762秒。没有包含素材锁定、剪点判断、封面制作或网络交付，不写成“一分钟自动剪完”。
- 源媒体横竖方向、非方形像素、明显音画起始偏移与时序错误在进入编码前处理；本入口不凭目标尺寸拉伸错误画幅，也不通过两路各自归零掩盖源偏移。

## 气口与笑声

- 普通气口以输出 **0.25–0.30 秒**为起点；本来更短且自然的间隙不再机械裁切。1.1×时，输出0.30秒对应源约0.33秒，不能把源0.30秒误当输出目标。
- 大笑的爆发、吸气、连笑、喘笑、表情和笑后反应都保留；识别器未给笑声文字、VAD标为非语音或出现短暂低能量，不等于可删气口。
- 父亲/对谈者的短回应、低声发音、情绪停顿保留。车内、户外等背景声打断静音检测时结合原声和波形；不要把整个 ASR 文本空档当静音裁掉。
- `尽量 ≤0.30秒`是节奏目标，不是吞字或删笑声的硬切指令；保护声音优先。确认空白可收紧，发音边界含糊则保留并只复核局部。
- 不删正文、不改原叙事顺序，不把“简单剪气口”解释成删重复、前置钩子或改写故事。

## 抖音／视频号格式

- 正式视频默认 **1080×1920、9:16竖版**；手机小体积预览保持同一9:16比例。
- 主发布封面是9:16竖版，标题原文不改；其他平台封面槽要求的比例独立裁切，不因此把视频正文改成横版。
- 多帧横排检查图只用于内部 QA，不作为视频或发布封面交付；最终链接明确标“9:16竖版”，手机播放器保持竖版显示。

## 耗时记录

用户手动快时约1分钟是流程参照，未实测的自动链路不得承诺一分钟完成。记录实际锁片、正文处理、封面、编码与交付耗时；以端到端时间评估，不拿一次12.7秒编码当全流程成绩。本次父亲创业视频因选错片、扩大无关转写、额外双ASR与字幕、串行封面造成拖长；这些是要消除的流程浪费，不作为必要步骤保留。
