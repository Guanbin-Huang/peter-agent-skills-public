分类/比较/候选选择默认必经 [StartLux 协议](../../startlux-decision/references/video-selection-v1.md)，无须用户再次点名。下表 GPT 型号/effort 用于证据观察、语义整理、候选生成、复杂验证与实现，不替代 StartLux 的候选选择；固定参数解析和确定性机械工作仍为工具。Plan 标记每个判断的 StartLux 输入/输出/源版本，成功回执可复用。此条覆盖旧的“由 Sol/Luna 直接选择”表述；共享 EDL 与原有审核/验收要求保留。


## 执行前先展示 Plan（2026-10-01 用户确认）

最小定位检查后、实质执行前，展示简短 Plan；按任务逐项选择下表的工具、完整模型 ID 和思考强度，而不是开了并行就视为完成调度。模型与强度是本轮起始选择，主会话配置保持；缺少 actual telemetry 时只记录 requested，不声称已切换。

```text
交付与验收：本轮具体成品、完成条件。
串行前置：输入/最新版/缓存检查 → 冻结必要时间线或修改点。
执行安排：任务｜可并行/须串行｜工具或完整模型 ID｜effort｜选择原因｜输入与独立写入范围。
汇合：依赖何时齐备 → 小样/局部验收 → 本轮渲染或拼接 → 实际文件与预览回读 → 交付。
```

- 简单单点修改只给一句话 Plan，直接使用既有脚本/工具；无需新增计划文件、另开代理或重复确认已经明确的需求。
- 对用户展示的 Plan 省去负责人/owner 字段；内部保留必要的独立写入边界和共享状态单写入控制。
- 执行前检查输入齐备、没有未满足的前后依赖、写入不会互相覆盖、共享状态与资源占用不冲突；确认能并行且收益大于协调成本的部分就实际并行，不只列计划后全串行。存在依赖或冲突的步骤按顺序执行，不为凑并行强行拆分。EDL/共享状态/最终封装保留单写入控制；先决条件未齐备的分支仅准备候选，不提前修改共享时间线。
- 完整剪辑按现有粗剪冻结、独立包装、小样和成品验收顺序执行；轻量返修先命中 `video-quick-revision`，复用正文/音轨/有效验收，只处理变更与边界，不绕回新片流程。封面、字幕与音效的本片具体顺序由当前依赖决定，不根据一句未展开的“要调整顺序”新增全局规则。
- 任务超出原分工时立即更新 Plan：时基/同步/跨资产错误交给时间线 owner；同类尝试没有新增证据时先定位根因，再决定接管或升级，不让低档分支继续猜切点。缺文件、依赖或编码参数不一致优先用工具修复，不机械升级模型。
- 每个有意义阶段记录实际耗时、失败根因和返工次数；有效检查复用，验收与交付回读完成即返回最新目录/文件/预览。用实际完成时间和质量评估分工，不用代理数量、模型名称或局部预检速度代替端到端提速证据。

## 并行分类：先分三类，再过两道执行检查

按每个工作块的当前输入、依赖和共享状态分类，而不是看起来有多个任务就开多个代理。分类针对当前阶段：B 类的前置完成后可以转为 A 类。冲突消除前保留串行。

| 类别 | 判断 | 剪辑中的例子 |
|---|---|---|
| A 现在就能并行 | 输入齐备，读取冻结版本，互不依赖，输出独立且无共享状态冲突 | 媒体参数探测与已选字体检查；已确定封面编辑与指定音效素材规范化；不同唯一音轨的ASR也可归此类，但必须过资源检查 |
| B 等前置完成再并行 | 共同前置尚未完成；只等本分支实际需要的输入，不等无关分支 | 正文/速度/字词时间和共享原子词组冻结后，字幕排版、封面以及已启用B-roll分别制作；字体小样等不依赖最终时间线的检查可提前做 |
| C 当前必须串行 | 存在数据先后关系、同一可变文件/时间线写入或同一GUI状态冲突 | 内容取舍→唯一时间线；最终音频→对应字幕对齐；资产汇合→封装→最终媒体验收；同一编辑器中的打开→选图→保存 |

两道执行检查同时适用于 A 类和前置已完成的 B 类：

1. **资源检查**：逻辑独立不等于机器能同时跑满。ASR、视频编码、GPU/内存/磁盘或网络密集任务按实际余量限流；共享GUI单写入。先用代表性小批观察耗时/资源，资源争抢导致更慢时降低并发，不按代理数量推断媒体进程容量。
2. **收益与执行方式检查**：机械工作先用脚本/专用工具批量或并发；简单改字直接完成。需要独立推理且拆分收益大于上下文传递/启动/汇合成本时才开子代理，模型与effort按任务难度单独选。安全且划算的并行必须实际发生，不只写在Plan里。

反例：字幕与封面是两个文件，也要确认共享时间线已冻结；只读校验若读取正在变化的资产，先锁定版本；多个任务共用GPU时不要全数同时启动；ASR没有完成时不编造词级时间；新增插入改变时长后，先更新映射再验收后方字幕。内部写入分工保留在执行层，用户Plan只展示分类、依赖、工具/模型与强度。

可复用计划格式：
```text
现在并行：…（工具/模型，effort；已满足的条件）
等待前置后并行：…（等什么输入）
必须串行：… → …
资源与收益：重任务并发上限依据…；简单步骤直接完成。
验收交付：…
```

本表是**任务启发式，不是模型能力、速度或费用基准**；不替代四核心 sub-skill 的内容/技术门禁。执行前先识别本轮是模式 A（词级审核/FCPXML）、B（仅文本字幕）、C（多素材 Preview→成片）、已批准成片包装、纯字幕改字，还是批注复盘；只运行命中路径。默认保留真实原声、完整音节、因果链/结论/用户点名金句。已确认术语显示为“酥神/酥神计划”；只修字幕同音误写，不擅自改原声。用户已指定新转录入口为**本地 WhisperX**：转录 → 词级对齐 → 对谈 pyannote 说话人分段与词级标签合并；详见 [WhisperX转录与说话人分段-v1.md](WhisperX转录与说话人分段-v1.md)。已有有效缓存按 ASR/对齐/说话人三个阶段分别复用。

## 视频轻量返修覆盖条款（2026-10-01）

改字、改字母、挪字幕/标题、调整字号、挪截图、明确时段的指定文字补充，优先 `video-quick-revision`。确定性修改由现有脚本/工具完成，不调用额外模型；需局部短文本或视觉判断时 `gpt-6-luna` low，轻微歧义 medium。本条覆盖下表对此类任务的常规 Sol 起始配置，不改变主会话模型、不为切模型启动代理、不声明未经实际调用验证的模型切换。正文/速度/素材时序变化及复杂问题继续沿用原表。

- 先用代表性转录片段和一个内容候选核验方法；后续比较验收通过率、耗时与返工，记录实际返回的模型证据，再决定扩量或调整。型号登记不等于已经执行了该型号任务。

## 选型规则

- **无 LLM**：`ffprobe`/`ffmpeg`、本地 WhisperX、解析器、确定性字符串替换、指纹/缓存、分段渲染、导出、范围/哈希/解码/时序脚本。工具结果由任务 owner 核验；“无 LLM”不等于免 QA。
- **`gpt-6-luna` low/medium**：范围固定、可用源时间/原话和脚本验收的提取、分类、候选元数据；**不得**单独决定正文删除、角色最终归属或改唯一 EDL。
- **`gpt-6.1-sol` medium**：日常语义整理、听证据后校对、字幕断句/封面语义行、普通局部返修和复盘归类。
- **`gpt-6.1-sol` low/medium**：要求明确的小修改、提取和格式整理用 low；已拆清的方案实现、字幕/版式、一般调试和局部集成用 medium。局部执行确需更多推理才用 high；机械时间映射/变速/验收直接用脚本。
- **`gpt-6-astra` high**：复杂、多模块、烧脑或模糊任务的分析/规划/关键决策，包括重大证据冲突、真正复杂的叙事与内容取舍、难以区分的情绪/笑点、关键排错。先明确输入、未知、依赖与验收，再交 Sol low/medium 执行已清楚部分；不作为每个普通步骤的强制监督者。缺文件、字体、依赖等确定性问题直接修根因。
- reasoning effort 随本任务难度选，不是把全项目提到 high。模型不可用时记录 `requested_model/effort`、`actual_model/effort` 与原因；当前根会话不能假称已切换。轻量模型与低 effort 不降低原定验收门槛。

## 手剪参考揭示的高难度工作（Astra high）

2026-09-24 用户提供的手剪版复盘表明：主要调整集中在开头约 20–30 秒，后半段有功能的重复和论证基本保留；“保留原逻辑”保护事实、因果、结论、金句，不等于逐字全留。该高难手剪语义复盘由 **Astra high** 作内容决定；新片的常规同类判断先用 **6.1 Sol high**，遇重大证据冲突再升级。Luna 只提候选，6.1 Sol high 把已批准区间准确实现为 EDL。

## 有界依赖 DAG 与资源预算

```text
路径选择/只读探测 ─┬─ 唯一音轨 WhisperX（ASR/对齐/分段）─ 候选 ┐
                  └─ 逐字稿/角色/样式候选 ──────────┤
                      → 启动卡 confirmed → 唯一 EDL → fineKeeps/1.3x/同步
                      → upstream_bundle + atomic-units 冻结
                      ├─ 字幕资产 ───────────┐
                      ├─ 封面资产 ───────────┼─ manifest/SHA 汇合 → 音频/长段样片双门 → Preview → 实际字节验收
                      └─ 已启用 B-roll/贴片候选 → 等字幕 bbox → 布局 ┘
                      → 批注局部串行合入 → 流程一通过 → 流程二通过
                      → 已批准输入/音频/字体预检 → 高清+可编辑工程 → 交付 QA
```

运行时最多 **4 个 agent 含主 Agent，即至多 3 个子 Agent**；只在输入齐备、写入目录独立、协调收益高时派遣。本地 WhisperX 默认先 1 路，确认内存/CPU 余量后可升至 2 路；这是保守起点而非性能测试结论。ASR 进程数与子 agent 数量独立，避免 ASR 与视频编码同时抢满 CPU/GPU。小修改直接执行，不 fan-out。GUI、活动 Preview 服务、`active_release` 和唯一 EDL 都单写入者。不同版本/时间线不能并行写同一个发布目录。上游 EDL/timing/speed/媒体变更使视觉旧验收失效；纯字改动只失效目标字幕和相关烧字缓存。

### 执行优先级

用户本轮明确要求优先；本路由只选择执行者与并行顺序，不擅自改变既有内容标准、语速或验收。新 ASR 统一走本地 WhisperX；对谈启用说话人分段，单纯改字幕跳过此链；现存 `run_transcribe.sh` 仍是云端历史工具而非默认入口。启动卡已有 confirmed 或用户明确给全选项时不重复确认；否则先完成只读判断。用户已给标题按原话，已批准封面直接复用；标题缺失只准备静帧候选，不提前启动高清主体。横版正片的黑色上下区是画布规格，与封面无黑边要求分别处理。
