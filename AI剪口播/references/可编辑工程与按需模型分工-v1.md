# 可编辑工程与按需模型分工 v1

适用：新口播剪辑默认同时交付**可编辑工程**和**发布版 MP4**；本轮已完成的媒体不因更新流程文档而自动重建。`AI剪口播` 继续担任总控和唯一时间线 owner；内容、气口、字幕、封面、B-roll 的既有职责不变。

## 两种“可编辑”，交付时必须说清

| 交付物 | 可编辑范围与验收 |
| --- | --- |
| 剪映原生草稿 | 按 `jianying-douyin-draft` 将素材和 SRT 真正导入时间线，形成独立字幕轨并应用字幕样式；保存后**重开草稿**，回读字幕条数、首尾时间及代表性字幕属性。只有这些检查通过，才称为“剪映可编辑字幕工程”。 |
| AI 可移植工程包 | 包含无烧字的干净 A-roll/master、**当前权威时间映射**、SRT、ASS 与字体/样式依赖、相关资产引用和发布版 MP4；校验引用可解析、字幕与当前时间线一致。它便于重新渲染或导入其他编辑器，但不等于剪映原生草稿。 |

文件同处一个文件夹、只有 SRT，或把烧字 MP4 导入剪映，都不能证明字幕文字在剪映里可编辑。SRT 本身也不携带 ASS/剪映中的字体、阴影等视觉样式。交付时分别标明两种工程的实际状态，不把“可移植”写成“剪映已落地”。

## 时间线与局部改字

唯一 owner 维护最新 `sourceKeeps/fineKeeps`、倍速与输出时间映射。人工裁剪一旦改变时长或切点，先更新权威映射和当前字幕 timing，再生成工程包及发布版；旧 SRT/ASS 不能仅因文件还在就复用。

纯文本纠错且时间线未变时，**跳过 ASR、重剪和音频母版重做**：只改命中的 cue 文本，预览改动 cue 及相邻 cue，核对字形、断句、时间边界，再渲染受影响的烧字视频。发布版 MP4 仍须实际渲染和验收；只在编码参数、时间基/PTS、片段边界兼容且缓存 manifest 命中时复用未受影响分段。不得把“字幕文件已改”说成“视频已改”。

当前文本补丁 CLI 的调用约定：

```bash
python3 scripts/patch_caption_text.py --srt captions.srt --ass captions.ass --old 苏神 --new 酥神 --out-dir NEW_DIR --expect-cues 4
```

预期新目录产出 `captions.srt`、`captions.ass`、`caption_patch.json`，其中记录 changed intervals，且 `media_rendered=false`。该 CLI **不**修改剪映草稿，也**不**自动渲染 MP4；以实际运行结果和文件回读为准。

## 按任务选模型，而非全程 Astra

详细任务归属、推理强度、升级条件和并行依赖统一使用 [任务模型与并行路由-v1.md](任务模型与并行路由-v1.md)，不在本文件维护另一张分工表。确定性替换直接用脚本；ASR 使用本地 WhisperX，编码由 FFmpeg 执行。模型选择是可测的起始策略，不是固定能力排名；记录实际请求的完整型号与 effort，不声称当前总控已切换。

可复用短指令：

```text
以 AI剪口播 为总控，先确认当前权威时间线和用户要的是原生剪映草稿还是 AI 可移植包；新剪辑默认两者可编辑交付状态分别核验，并交付发布版 MP4。纯字幕文本修改只更新 SRT/ASS 的目标 cue，检查相邻 cue 后按兼容缓存局部重渲染，不重跑 ASR/重剪/音频。按任务难度选择并记录实际模型与 effort；剪映草稿必须重开验收，MP4 必须完成渲染与解码检查。
```

最小验收：① 最新时间映射与字幕首尾、改动 cue 及相邻 cue 对齐；② 原生剪映草稿若声称完成，重开后字幕轨与样式可编辑；③ 可移植包资产与样式引用可解析；④ MP4 渲染完成并可解码，所展示文件就是已验收版本；⑤ 记录实际模型分工和未完成项目。

## 当前型号依据与推理强度

2026-09-30 核对当前 Codex 运行时与本机模型登记：新增日常/工程任务采用 `gpt-6.1-sol`，常规重要内容方案与叙事取舍优先 `gpt-6.1-sol` high，重大证据冲突及高难手剪复盘使用 `gpt-6-astra`，边界固定的候选提取使用 `gpt-6-luna`；确定性任务沿用专用工具。模型 ID 与 reasoning effort 独立选择，详细任务矩阵只在 `任务模型与并行路由-v1.md` 维护。登记说明是起始选型依据，不是同素材性能测评；既有明确配置及运行中的任务保持原值，不因更新文档自动改派或重建。

复杂且高返工成本的任务可一开始选 Astra，不必机械地先让小模型失败。提高 reasoning 不会补齐缺失文件、权限或坏工程结构。以同一组真实任务的验收通过率、总耗时和返工次数选择满足质量门槛的轻量配置；不要只按单 token 价格或假定 high 总优于 medium。
