# 输出成品快速路径 v1

目标：`AI剪口播` 先完成粗剪，`clip-fine-cut-rhythm` 再从原片时间线精剪气口，正式高清只做一次重编码。所有高概率失败在精剪、1 秒冒烟测试或音频母版阶段暴露。

## 仅改字幕文字的入口

先按 [可编辑工程与按需模型分工-v1.md](可编辑工程与按需模型分工-v1.md) 判断返修类型。时间线、样式和音频均未变时，修改独立字幕资产，复用已有音频/同步验收并仅检查变更页和边界；不要重新执行下列新片粗剪、变速或独立 ASR 流程。新片仍按下列顺序，并同时保留可编辑工程材料与发布 MP4。

## 固定流水线

0. **粗剪确认后先做 clip 精剪**
   - `AI剪口播` 产出并冻结已批准的原片 `sourceKeeps`；这一步只代表粗剪通过。
   - 调用 `clip-fine-cut-rhythm`，输入原始素材、`sourceKeeps` 和逐词 timing，默认只缩短过长空白气口。
   - 输出 `fineKeeps` 和精剪时间线；不生成中间高清。找不到 clip skill、缺少 `sourceKeeps` 或 `fineKeeps` 越出粗剪范围时立即 STOP。

1. **冻结输入并写 manifest**
   - 固定已批准粗剪 EDL、精剪 `fineKeeps`、逐字 timing、封面标题、字体、片尾路径和输出规格。
   - 对这些文件和参数计算哈希。哈希未变时复用缓存，不重跑 ASR、封面、片尾或高清主体。

2. **先做音频母版，再独立 ASR**
   - 按最终整数帧 EDL 生成完整音频母版；它必须与最终成片使用同一份音频内容。
   - 在音频母版上跑一次独立 ASR，对齐并修正最终字词 timing。
   - 先运行字幕数据校验。任何 0 时长、倒序、跨素材页或 P95 超阈值都在高清编码前修复。

3. **运行成品预检、字体冒烟与长段时序小样**
   - 运行 `scripts/final_product_preflight.py`，检查 EDL 连续性、源文件范围、逐词时间、中文字体和片尾。
   - 先按 `多视频Preview快路径-v2.md` 和 clip 的 `音画时序验收-v2.md`，用实际渲染链跑编号帧回归及代表性6–10秒长段音画小样。1秒字体小样不替代时序检查；失败不启动高清。
   - 用最终相同 filter graph 渲染 1 秒 1080×1920 样片，必须包含中文、英文、两行字幕和阴影。
   - 默认 `cover_frames=3`、`cover_mode=replace_first_frames`；编码前在代表性短样中检查封面第 1、3 帧及正文第 4 帧，正式编码后对最终文件再检查这三帧。中文缺字、字体回退、文字越界或 frame 4 仍残留封面时立即 STOP。封面位置沿用 douyin-cover 的中间偏上规则，保留眼睛、眼镜与脸部表情。

4. **一次正式编码**
   - 主体、封面片段和固定片尾分段缓存；参数一致时通过无损拼接/封装合成。
   - 封面标题变更更新 PNG 和成片前 3 帧；参数、关键帧与 PTS 兼容时只重做封面段并复用正文，不误称所有项目都能无损拼接。替换前三帧画面不改变音轨、总时长或正文字幕时间。
   - 字幕文字变更只使受影响字幕页所在的编码缓存段失效；兼容的未变区段和音轨直接复用。分段编码参数、关键帧或 PTS 不满足拼接条件时，重编码对应主体，不承诺所有工程都支持局部无损拼接。
   - 字幕 timing 变更需重新计算受影响区间并校验边界；正文 EDL 和音轨未变时不重剪、不重跑 ASR，固定片尾复用缓存。
   - 禁止为了调试整片 filter graph 直接启动长编码。

5. **只做交付验收，不再反向改字幕**
   - 调用 `clip-fine-cut-rhythm` 的 Delivery Gates：`ffprobe` metadata、软件整片解码、macOS VideoToolbox 整片解码、每 5 秒及剪切边界硬件抽帧、音画首尾差检查。
   - 增加逐段原片画面时间映射和独立音轨比对；底片检查通过不能替代镜像/B-roll/封面包装后的参考变换与覆盖边界验收。网页/附件实际媒体哈希必须对应当前验收版本。
   - 任一错误日志非空或画面花屏立即 STOP；软件解码通过不能替代 VideoToolbox 验收。
   - 最终音轨与已验音频母版哈希一致时复用已有转录/对齐；哈希不同只证明字节变化。仅换容器或音频重编码，若同一人声源、EDL、速度与语音时序保持且新输出解码、边界和源映射验收通过，仍复用已有语音证据，不自动重跑整片 ASR。更换 BGM 时核对干净人声来源与混音契约，不以混音波形变化推断正文变化。
   - 正文剪点、速度、说话内容变化或出现真实漂移时，让受影响的对齐证据失效，重做相应时间映射/对齐；疑词局部回听或局部 ASR。只有语音证据缺失或确实全局失效才补完整转录。未变化的原片转录继续复用，最终文件的相关同步与解码验收不省略。

## 缓存键

| 产物 | 缓存键 |
|---|---|
| 音频母版 / 独立 ASR | EDL + speed + source fingerprints |
| 字幕 timing / SRT | 音频母版 hash + retained transcript + atomic units |
| 封面 PNG / 3 帧片段 | title + selected frame + font + style |
| 高清字幕主体 | EDL + source fingerprints + SRT + render settings |
| 固定片尾 | outro fingerprint + output codec settings |

任一缓存必须有 manifest 证明命中。只凭“文件名看起来一样”不得复用。

## 失败分支

| 触发条件 | 一线修复 | 仍失败时 |
|---|---|---|
| 缺少 `fineKeeps` 或 clip skill | 回到已批准粗剪时间线，调用 `clip-fine-cut-rhythm` 生成并冻结精剪时间线 | STOP，不得直接高清包装 |
| 中文字体冒烟测试失败 | 改用显式 `fontfile` 的 `drawtext`，不要依赖系统 fallback | STOP，修字体资源后再运行 |
| 独立 ASR 漏掉重复/含混字 | 对齐器保留原文并为漏字插值正时长 | 人工校对该句，不删除已确认原话 |
| 用户在渲染中改封面标题 | 终止尚未完成的封面段，更新 title 缓存键 | 主体缓存保持，不重编码主体 |
| 字幕校验失败 | 修 timing/SRT 后只重做字幕主体 | 不重跑原片剪辑、不重做片尾 |
| 最终 A/V 或帧数失败 | 检查分段帧数与音频母版长度 | STOP，不以播放器“看起来正常”放行 |
| VideoToolbox 报 `-12909`、硬件解码错误或抽帧花屏 | 从原片和 `fineKeeps` 按 clip 兼容参数重渲染 | STOP，不重编码损坏文件冒充修复 |

## 进度反馈

长任务只报告真实阶段：`预检`、`音频对齐`、`冒烟测试`、`高清主体编码`、`片尾/封装`、`验收`。编码中每 60 秒报告进程是否存活、已运行时长和最近动作，不伪造百分比。

## 交付位置

交付 MP4 后明确返回实际绝对目录、视频文件链接与最新预览链接；封面图片另列，不把封面路径当作视频目录。


## 已确认工程的提速与验收收尾（2026-10-04）

1. **只执行冻结工程**：已有 EDL/ASS/封面/已验音轨时，直接复用；不得再次剪内容、ASR 或提速。明确「没有片尾」即 `outro=none`，不追加默认片尾。保留已验高清分段，缓存键包含源版本、EDL、字幕、字体、封面、编码器与完整编码参数。
2. **固定机械工具，不让每个 agent 重写生产链**：同一批共用已验渲染/验收脚本和字体路径。用户要求多个 agent 时按集划分独立目录，但复用工具；模型处理异常和内容判断，不逐段解释机械命令。媒体进程并发按本机同样本吞吐测试限流；三个 agent 不等于三倍编码速度。
3. **关键帧 seek + 精确 PTS 抽图**：CFR、零起始时钟、整数 frame tick 的已封装成片，用下方脚本抽首1/3/4帧、切点和末帧。不要每取一张图都从头解码整片。工具必须匹配精确 PTS；目标缺失时报错，不能用最近帧冒充。软件/VideoToolbox 全片解码门禁仍保留，每份同哈希成片各做一次。

   ```bash
   N=$(ffprobe -v error -select_streams v:0 -show_entries stream=nb_frames -of csv=p=0 FINAL.mp4)
   LAST_FRAME=$((N-1))
   /Users/peter/.local/share/uv/tools/whisperx/bin/python \
     /Users/peter/.codex/skills/AI剪口播/scripts/extract_frames_exact.py \
     FINAL.mp4 --frames "0,2,3,$LAST_FRAME" --output-dir qa-frames
   ```

   `LAST_FRAME` 是已验帧数减1。该工具只处理已有 CFR 成片，不用于 VFR 原片时间推算。
4. **结果逐项落盘**：每个命令完成立即保存 command/input/stdout/stderr/exit/status。验收报告打印、图片提取或网页加载失败时，只修对应阶段，复用已有同版本成功解码、音轨 hash 和源映射证据；不要重新扫整片来补一行报告。
5. **验收通过即交付**：某集媒体验收通过，立即发布该集聊天视频附件并回读 `ok:true`，同时报告文件目录。云上传、网页截图不阻塞已通过的附件交付；网页验证另行完成，不把尚未验证入口说成可用。公开入口等待 DOM 就绪，然后检查实际视频 metadata/尺寸/Range/播放进度；不把所有高清 poster 图片的 `window.load` 当作播放就绪。
6. **硬件编码先做同源带字小样**：以原片、同一 EDL/字体/ASS/画幅/时钟生成 CPU 和硬件 6–10 秒样本；确认帧数、封面/字形、首尾时钟、软件/硬件解码和实际画质。编码器切换使旧编码缓存失效，不拼接不兼容的 CPU/硬件片段；音轨和 ASR 缓存仍可复用。质量不达标时仅淘汰该配置，已验成片不动。

本机一次 8 秒夜间口播小样：CPU `libx264 veryfast CRF18 threads2` 3.29 秒；`h264_videotoolbox allow_sw=0 b:v=16M maxrate=24M bufsize=32M` 1.38 秒，VMAF 相对 CPU 均值94.30/P5=88.81。8M 配置均值87.58，已淘汰。该结果只作为这个素材类的小样候选；新素材/滤镜/硬件/FFmpeg/字体必须重做对应小样，不承诺全流程同比提速，不将16M设为所有项目的固定码率。

精确末帧工具本机实测：从头按 PTS 扫描18.12秒，关键帧 seek0.81秒，两张1080×1920 RGB PNG逐像素相同；首1/3/4、切点和末帧共5帧验证通过。具体项目路径和临时测量文件只在项目报告，不写成全局偏好。
