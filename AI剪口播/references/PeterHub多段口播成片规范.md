# 多段手机口播 Preview→成片规范

用于“几段手机录制视频 + 一份逻辑逐字稿 + HTML 审核 + 最终成片”的重复工作流。PeterHub 是其中一个包装场景，不改变本流程的 Preview 闸门。

> 依赖顺序、3–4路并行、音画小样和实际媒体入口验收以 [多视频Preview快路径-v2.md](多视频Preview快路径-v2.md) 为准；先读该文件。本页保留包装约定。

## 1. 默认快路径

1. 检查每段素材的画幅、帧率、音轨、时长和开头结尾，并行完成词级 ASR。
2. 把用户逐字稿拆成逻辑章节，用真实 ASR 将各段表达大致放回对应章节；同一章节有多个 take 时保留表达最完整、最自然的一遍。
3. 完成初检：在逻辑粗拼后只清理三类内容——明显废话与过度重复、拍摄现场的剪辑指令、与 IP 导演或助理的拍摄对话。
4. 初检结束并冻结 EDL 后，并行完成字幕/音频先验与实际长段音画小样；汇合通过后一次编码 Preview，完成源时序/字幕/解码验收，再验证 HTML 实际媒体字节；只有用户本次明确要求“无字幕”时才跳过字幕。不把 Rough Preview 当作独立交付或额外审核阶段。
5. 在 HTML 中循环完成 M/Comment、Codex 返修、流程一逐块审核和流程二完整低清检查。任何未确认阶段都不渲染高清。
6. 用户明确确认粗剪后，调用 `clip-fine-cut-rhythm` 从原片 `sourceKeeps` 生成精剪 `fineKeeps`，默认只缩短过长空白气口，不输出中间高清。
7. 从原片和 `fineKeeps` 一次输出高清正式版，并按要求加入字幕、封面、片尾或其他包装。
8. 调用 `clip-fine-cut-rhythm` 的全部 Delivery Gates 验收最终包装文件后交付。

参考逐字稿是逻辑地图，不是必须复刻的台词。表达不同但语义相同，直接使用真实口播；逐字稿有而素材没有的内容不得补造。

## 2. 四个阶段与画质闸门

| 阶段 | 用户界面/交付物 | 默认画质 | 允许的工作 |
|---|---|---|---|
| 初检 | 无单独用户交付；完成后直接打开 HTML | 生成 270×480、30fps、CRF 30、AAC 96k、带规范字幕 Preview | 素材体检、ASR、逻辑粗拼、三类清理 |
| HTML 审核循环 | 完整 Preview、局部返修、流程一、流程二都在 HTML 内 | 全部同上 | M/Comment、试剪、返修、逐块通过、完整低清复查 |
| clip 精剪 | `fineKeeps` + 精剪时间线 | 不输出中间高清 | 从原片时间线缩短过长气口，保持内容、语速和字幕文字 |
| 最终成片 | 发布版 | 按平台要求输出高清 | 字幕、封面、片尾及最终包装 |

倍速从本轮目标继承，所有 Preview 与最终版使用同一节奏，避免低清审核通过后高清版本听感变化。Preview 字幕属于审核必需层，不视为提前包装；调用 `douyin-captions`，按正式画布等比缩放。用户未明确确认最终成片前，不允许做封面、追加片尾或输出高清。

**阶段边界：初检一结束就进入 HTML 审核循环。不存在“先把 Rough Preview 单独发给用户，再决定要不要进入 HTML”的中间步骤。**

## 3. 功能触发矩阵

| 功能 | Preview 阶段 | 最终成片阶段 |
|---|---|---|
| 多段 ASR、逻辑排序、三类清理 | 开启 | 复用已确认时间线 |
| `clip-fine-cut-rhythm` 气口精剪 | 粗剪确认前关闭 | 粗剪确认后、正式包装前强制开启 |
| 字幕 | 默认开启；明确要求无字幕时关闭 | 按发布默认或用户要求开启 |
| 标准片尾、前 5 帧封面 | 关闭 | 按发布默认或用户要求开启 |
| FFmpeg 发布压缩 | 关闭，仅做超低清编码 | 开启 |
| 人像抠图、换背景、背景颜色 | 关闭 | 用户明确要求或随素材提供背景图时开启 |
| 人声降噪 | 关闭 | 用户明确要求时开启 |

用户提供背景图时，不再追问是否换背景：直接做人像抠图并换成该图。只因 skill 内置了 PeterHub 背景、但用户本轮没有提供或提及背景时，不自动换背景。

## 4. 多段 ASR、逻辑拼接与粗剪

- 多段素材使用 `scripts/batch_transcribe.sh`，默认并发3，`BATCH_JOBS=4`支持4路；先对严格相同素材去重，复用源指纹匹配的ASR。
- 按用户已确认偏好，batch默认走已授权的Seed ASR标准submit/query路径，资源`volc.seedasr.auc`；显式flash/auto选项保持兼容。欠费/授权/限流分别报告，不无依据地归咎并发。
- 用户已经明确要求直接成片时自动进入模式 C，不再停下来要求选择模式。
- 先把逐字稿拆成逻辑章节，再把各段 ASR 的完整表达匹配到章节；章节顺序服从逐字稿逻辑，同一章节内优先选择最自然、最完整的一遍。
- 顺序优先级固定为：用户本轮明确指定的片段顺序 > 逐字稿逻辑顺序 > 原文件顺序。不要让旧项目的“保留文件顺序”覆盖本轮提供的逐字稿结构。
- 不要求真实表达与逐字稿逐字一致。逐字稿负责“先讲什么、后讲什么”，真实录音负责“实际说了什么”。
- 参考稿有、录音没有的段落不得补造。录音有、参考稿没有的完整表达不得机械删除。
- 初检只删除：①明显废话和过度重复；②“这段要删掉 / 那段剪掉”等现场指令；③“可以了，这段拍好了”等与 IP 导演、助理的拍摄对话。
- 识别现场对话必须结合上下文、说话对象和拍摄语境，禁止只靠关键词批量删除。初检阶段不做逐个口癖清扫，不压缩所有停顿，不制造密集碎切。
- 遇到专有名词误识别，例如 `HC` 被识别成 `Hacker`，只纠正字幕与分析稿，不改原始 ASR 响应。
- 正片加速必须同时作用于画面和声音。长期默认是 1.3 倍速；一次性覆盖不写回长期默认。
- 渲染前写 speed manifest；输入已经是 1.3 倍速时不得再次套用，无法确认则回到干净原片重建。

## 5. 可选抠图与换背景

只有明确触发时才读取本节。

1. 每段源视频分别做时序连续抠图，再按剪辑时间线拼接；不要先跳剪再让 RVM 跨切点传播状态。
2. 每个切点重置 RVM recurrent state。
3. 每段先检查构图，再决定是否保护纸张、桌面或其他前景道具；不得套用固定下沿保护区。
4. 发丝细节优先。轻微灰边可接受，不要为追求纯净边缘切坏头发和手指。
5. 需要透明母版时输出 ProRes 4444；普通发布版无需保留 alpha。
6. PeterHub 背景位于 `assets/peterhub/peterhub-background.png`，分辨率为 1080x1920；用户提供其他背景时，本轮优先使用用户文件。

## 6. 可选人声降噪

只有明确触发时才读取本节。

- 优先用 DeepFilterNet3 加 post-filter 处理正片人声，片尾保留原声。
- 默认高通 70 Hz、低通 15 kHz，整体响度接近 -16 LUFS。
- 先抽查强齿音、轻声、笑声和句尾气息。出现水下感、金属感或吞字时降低处理强度。
- 只需替换音轨时复制原视频码流，不要无意义地重新编码画面。

## 7. 字幕、标题与封面

本节的发布标题、封面和最终包装只在用户已经确认流程二、`clip-fine-cut-rhythm` 已冻结 `fineKeeps` 后执行。Preview 阶段默认烧录审核字幕，但不得提前做标题、封面或片尾；封面仍从无字幕清洁源取帧。

- 1080x1920 口播调用 `douyin-captions`：剪映 15 号得意黑、白字、柔和黑阴影、无描边。
- 标题调用 `dontbesilent-title`：基于 dontbesilent 的内容共创方法。此阶段视频已冻结，使用正文固定分支，只在现有材料内优化标题与封面文案，不擅自重写开头或修改时间线；可修改内容的共创仅在策划阶段且得到用户授权时开展。
- 封面优先从用户指定时间点的无字幕清洁画面生成。没有指定时间点时，选择人物清楚、手势稳定、构图完整的一帧。
- 不要从已经烧字幕的成片上擦字。应从无字幕中间片或透明母版取帧。
- 30fps 发布版中，第 1-5 帧为封面，第 6 帧恢复正片。封面只覆盖画面，音频从原始 0 秒开始，总时长不增加。

## 8. FFmpeg 最终压缩

普通发布版必须调用：

```bash
bash "$SKILL_DIR/scripts/compress_publish.sh" \
  input_master.mp4 output_publish.mp4 \
  --cover cover.png
```

默认策略：

- H.264 VideoToolbox 硬件编码优先，1080x1920 30fps 目标码率 6 Mbps。
- AAC 160 kbps，`yuv420p`，`+faststart`。
- 若硬件编码不可用或失败，回退到 `libx264 -preset veryfast -crf 22`。
- 封面嵌入和压缩必须在同一次编码完成。
- 不压缩透明母版；此处只处理普通发布版。

## 9. 验收

1. Preview 用 `ffprobe` 确认目标低清分辨率、30fps、H.264 + AAC；默认字幕必须调用 `douyin-captions` 并通过断句、同步、字体和等比缩放检查。1080×1920 基准为 76px，360×640 为 25.33px；得意黑、白字、柔和黑影、无描边。只有用户本次明确要求无字幕时，才验收无字幕版本。最终版调用 `clip-fine-cut-rhythm` 核对 profile、level、恒定帧率和 time base。
2. 对最终文件执行软件整片解码和 macOS VideoToolbox 整片解码；退出码非零或错误日志非空都不得放行。
3. 硬件解码抽查第 1、5、6 帧、每 5 秒、所有剪切边界、字幕最长页、片尾转场和末帧。
4. 检查音画首尾差、静音、损坏帧、花屏、黑尾，并运行 `clip-fine-cut-rhythm/scripts/verify_source_timing.py` 核验每段首中尾源帧时序及独立音轨；只看首尾差不足以证明口型同步。发布入口再核对真实媒体哈希与Range。
5. 若启用了可选模块，再检查发丝/手指边缘、背景漏色和降噪损伤。

标准片尾的定位顺序：本轮用户提供的片尾 → `assets/peterhub/standard-outro.mp4`。两处都没有时，不静默省略；先报告缺失，再交付无片尾版或等待用户补充。

## 10. 失败处理

| 触发条件 | 一线修复 | 仍失败时 |
|---|---|---|
| flash ASR 失败 | 检查 skill-local `.env`、资源额度和文件大小后重试 | 改用 standard submit/query，并记录引擎 |
| 参考稿与 ASR 冲突 | 回听原声并以录音为准 | 把不确定句列给用户，不自行补造 |
| 自动顺序无法确定 | 先按逐字稿章节匹配 | 同一章节仍不确定时保留文件顺序，并在 HTML 中让用户审核；不为小歧义阻塞粗剪 |
| 缺少 `fineKeeps` 或 clip skill | 从已批准 `sourceKeeps` 调用 `clip-fine-cut-rhythm` | STOP，不得直接进入最终包装 |
| VideoToolbox 压缩失败 | 脚本自动改用 libx264 | 保留未压缩母版并报告 FFmpeg 错误 |
| VideoToolbox 解码错误或抽帧花屏 | 从原片和 `fineKeeps` 重渲染并重复全部 Delivery Gates | STOP，不重编码损坏文件冒充修复 |
| 封面尺寸不一致 | 按正片尺寸缩放并居中裁切 | 停止交付，避免拉伸变形 |
| 抠图或降噪效果伤害主体 | 降低强度并重渲染短样片 | 关闭该可选模块，保留正常成片 |

## 11. 反模式

- 不把参考逐字稿当作已经说出口的内容。
- 不要求真实表达逐字贴合逐字稿；逐字稿只规定大致逻辑顺序。
- 不在初检阶段精修每个口癖和气口；只做三类初始清理。
- 不在粗剪确认后跳过 `clip-fine-cut-rhythm` 直接包装，也不在低清 Preview 上剪气口。
- 不把超低清 Rough Preview 设置成 HTML 之前的独立交付或确认节点。
- 不保留现场剪辑指令和与 IP 导演、助理确认拍摄状态的对话。
- 不在最终成片确认前输出高清、做封面或片尾；Preview的规范审核字幕仍默认生成。
- 没有背景图且用户未明确要求时，不默认抠图、换背景、改背景颜色或降噪。
- 不先烧字幕再从成片擦字做封面。
- 不把封面作为额外静止片段插入，造成声音和总时长后移。
- 不对中间文件反复有损压缩。
- 片尾默认随整片使用 1.3 倍速，但不叠加正片字幕或背景；用户明确要求时才保留原速片尾。
- 不把单次倍速覆盖、标题、时间点或降噪参数写成长期默认。

## 12. 持续迭代

用户明确表示成片满意并要求沉淀时，提取可泛化的确认反馈，再用 `darwin-skill` 迭代本 skill。一次性项目参数保留在项目记录中，不写入长期默认。
