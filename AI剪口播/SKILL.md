# AI剪口播

以最小有效链路交付同质量视频：**内容/时间线负责“剪什么”，模板/项目参数负责“长什么样”，批注负责“改哪里”**。名字、既有工程和批注保持兼容。

## 用户确认的默认速度与气口（2026-10-26）

- 以后剪辑默认音画同步 **1.2×绝对倍速**，只应用一次；默认剪掉过长普通气口，在最终输出时间线上保留约 **0.30秒**，原本更短且自然的间隙不拉长。
- 本条覆盖旧的日常1.1×或未确认的模式默认；用户本轮明确速度、要求不变速/不剪气口，或返修已批准成片要求保持时序时，按明确范围执行，不重剪旧成片。
- 保护完整发音、笑声和有意义的反应；气口目标不是删除这些声音的依据。1.2×下输出0.30秒对应原速源约0.36秒；按输出时间线验收。
- 时间线建立时写入 `speed=1.2` 与输出气口目标0.30秒；渲染器读取明确EDL，不在包装/追加片尾时重复乘1.2。片尾速度按其独立指令确定。

## 默认自主选题与重组授权（2026-10-16）

用户说“帮我剪视频”“帮我剪一剪”“剪一下视频”“剪视频”“简单剪剪”，未明确限制选题/思路时，默认授权主控读取素材后自主发现选题、取舍和重组，直接制作低清审核预览；不要求用户补说“可以重组”，不因缺少选题而常规停在选择卡。

- 一批素材可对应一条或多条选题：跨文件同题归组，单文件多题可分片；按每条能否独立兑现和保有完整前提/结尾决定数量，不按文件数硬拆，也不把不同话题强拼。简短说明分组及重组思路后继续，选题概览不是新增批准门禁。
- 用户给定的任何具体选题、顺序、剪辑思路或保留范围优先。只给选题时在该题内自主组织；给定顺序/逻辑时沿用；明确“只剪气口/保留正文与顺序”时走轻量路径，不搬钩子、不另拆题。只有必要事实或真实冲突缺失时问对应一项。
- 有多个选题时，共用已验证的源素材/转录缓存，每条在自己的目录保存 brief、content_edl、字幕、预览及版本；“唯一EDL”指每条成片一个真源，不是整批强用一条时间线。分别出预览供逐条审核，不默认一次导出全部高清。
- 主控负责按需衔接 DB 分析与实际剪辑：`dbs-content-value` 判断观看任务与价值，`dbs-title-cover-intro` 比较真实钩子，`douyin-rough-cut` 落实源区间与顺序，随后由本 skill 汇合。携带自主委托来源和本片已定主线，不在各模块重复让用户选题。
- 这份默认授权满足常规自主剪辑的启动授权。记录 `preedit_decision.status=confirmed`、`decision_source=standing_user_delegation` 与实际推断依据；自选选题记为 Agent 推断，不冒记成用户指定或成片已验收。普通 B-roll 仍默认 none，身份贴片沿已确认默认；新风格样片、用户明确要求先 review、最终高清/发布等门禁分别保留。

此节优先于旧参考里泛化的“必须再回复按推荐才能粗剪”，以及把单独“简单剪剪”归为只剪气口的入口；当前明确约束始终更优先。

## 2. 不变的内容与质量契约

1. 保留完整发音、笑声的爆发/吸气/连笑/反应、有信息的追问和人物表演。静音/ASR空档不自动等于删除范围。
2. 日常轻剪保留原顺序和正文，常规无内容气口在输出时间线保留约0.30秒，默认音画1.2×且只应用一次。完整新片/双人对谈同样默认1.2×；本片明确批准的其他原素材绝对速度按当前指令复用，不从“双人”自动推定1.3×。模板包装从不施加速度。
3. 唯一内容时间线owner写EDL；先从原片确认take和顺序，再精剪气口。不得从损坏或烧字成片反推原片时码。
4. 新转录按[WhisperX协议](references/WhisperX转录与说话人分段-v1.md)执行；ASR、align、diarize分别复用，缺哪个只补哪个。确定性包装/改字零ASR。
5. [音画时序](../clip-fine-cut-rhythm/SKILL.md)按实际变更补验；元数据、总时长或ASR通过不等于口型同步。

6. 快切/接缝默认清理键盘、回车样敲击和异常click/pop；按 `clip-fine-cut-rhythm` 的“默认清理快切机械杂音”执行，保护完整发音和BGM。只改音频时复制已验视频码流，不重做画面、字幕或速度。

### 默认清理拍摄废段（2026-10-16 用户确认）

- 每次剪辑默认清掉“重新说”“重新来”“你再问一句”“你插进来”等拍摄指令、重拍准备和失败试说；按语境识别拍摄交流，正文引用这些词时保留，禁止关键词整段误删。
- 同一句的重复 take 只保留一个完整正确版本，沿用 `douyin-rough-cut` 的取舍规则；重拍指令后正式说出的提问与回答仍属于可用内容，保留完整发音和问答承接。
- 对谈按完整问答轮次整理，保留推动话题的提问、追问、质疑、自然接话、笑声和反应；清理拍摄废段时保护对话，不把对谈压成单人口播。删除范围与重复 take 取舍记入本片决策表；此默认规则不代表任何具体视频已完成剪辑或验收。

## 3. 模板与项目参数：数据修改，不逐片写合成器

- 可执行默认资产：`assets/templates/peter-talking-head-v1.json`。第一版支持批准的1080×1920/30fps SDR干净底片、已确认SRT和真实字体；不自动裁切，不把HDR当SDR贴标签，不新增HyperFrames依赖。
- 每项目保存`style.json`与`package.json`；项目参数只覆盖已声明的字幕字号、位置、颜色、阴影和避让区。字体文件及内容独立，不把某片名字/金额/坐标沉淀成全局默认。
- 构建器输出ASS；样张与视频共用该ASS和相同版式。先看开头/中段/末段及变化页样张，再看需要验证的短动效/接缝，最后编码；截图通过不代表听审通过。
- 改模板参数：以项目`style.json`重新build到新版本，只重做包装。不修改脚本结构，不重新转录/剪正文/提速。
- 该工具不做封面前三帧、片尾、B-roll、人物贴片或聊天布局：沿用领域owner和既有合成链，不默认为新字幕模板覆盖这些已确认风格。
- 完整`captions.ass`只给干净底片，不作为旧Review的增量overlay合入；禁止重复烧字。输出是新候选版本，原审批/批注保留，变更范围按既有审核规则失效。

命令与参数修改示例、输入边界、状态与量化测试见[模板参数化协议](references/模板参数化-v1.md)。

1. 冻结本轮实际变更和新版输入身份；技术工具状态与内容/视觉/听审状态分别记录。
2. 先样张与短样拦住字体、布局、时钟问题；正式编码后的解码、源相对同步、字幕可读与封面1/3/4帧按真实新增风险验收。
3. 只有实际验收与版本回读通过才切换`active_release`；打包成功不自动标记旧Review approved。
