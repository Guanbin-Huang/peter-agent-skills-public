# 林氏理解法

让读者从一个看得见、算得动的小例子出发，理解概念的位置与机制，并能迁移到新情境。固定主线：**toy sample → 同类 → 类比 → 完整数据流 → 细节补充**。

## 输入与准备

1. 从当前请求提取：目标概念、使用情境、已知基础、卡住的问题、指定材料、长度要求。没有基础信息时，标明“先按初学者、只用日常经验解释”，直接开讲；概念有多个领域含义且上下文不足时，只问领域这一个问题。
2. 只选择一个中心问题。大主题先围绕一个明确问题讲透，其余列为后续入口；用户列了具体问题时，将原问题保留为相应小标题，逐项覆盖。
3. 区分原材料陈述、教学设定、已经核实的事实。把案例里的表达方法迁移过来，技术结论按证据判断；学生觉得顺畅，仅说明表达有用，不等于事实全部正确。
4. 对影响主线的争议、版本归属、性能倍数和绝对化说法，定向查原论文、官方文档或固定版本代码。已有同版本可靠证据就复用。未核实的结论写明条件或待核，不用搜索摘要冒充阅读全文，不为一个概念泛搜整个领域。

## 固定五步

### 1. Toy sample：它到底在做什么？

- 一句话写出“面对什么问题，改变什么，得到什么”，接一个最小可推演样本。
- 明示“教学设定”。只保留 2–4 个对象或变量，给定输入、规则、一次变化和可观察结果；有计算时展示一组具体数字，并自行复算。
- 尽量用目标概念本身的缩小版本：两条记录、两个事务、两种选择、一维状态。豆子、橡皮擦等故事可辅助可视化，但故事后仍要有实际规则；只说“慢慢就变好了”不算完成。
- 先解释必需的 1–3 个术语。暂缓其余细节，并说清本例简化了什么。
- **完成标准**：读者能回答“起点是什么、刚发生了什么、终点是什么”，能预测规则再用一次的结果。

### 2. 同类：它在什么位置，和谁容易混？

- 给出上位问题或概念类别，再选 2–4 个真正相关的概念；数量不足时少列，不凑家族成员。
- 标明关系：同层替代、包含/特例、组成工具、前置基础、可组合维度。多个分类轴分开描述，不把能共存的机制排成互斥流派。
- 用共同维度比较“解决的问题、输入输出/机制、适用条件与代价”。非算法概念使用“判断对象、决策规则、忽略什么”等维度。
- 只在有证据时描述技术历史、性能和优劣；教学顺序不冒充历史演进或必然升级。
- **完成标准**：读者知道它属于哪里、与最容易混淆的概念差在哪、何时选它。

### 3. 类比：用我熟悉的东西重新看一遍

- 选一个读者确实熟悉的机制。没有已知专业背景就用日常经验；不默认初学者已经懂另一种复杂算法。
- 列出“熟悉对象 → 目标概念”的 3–5 组对应，必须映射操作关系，不能只映射名词外观。
- 明确至少一个类比失效点，再返回第 1 步的同一个样本解释它。类比帮助记忆，正式结论仍由真实机制支持。
- **完成标准**：读者能说出哪些地方相似，以及哪些推论不能从类比得到。

### 4. 完整数据流／机制链：每一步具体发生什么？

- 给一条从原始输入/初始条件到最终输出/决策的完整链，避免在“模型处理”“系统算出结果”处跳过用户卡住的步骤。
- 逐步列出：谁执行、拿到什么、按什么规则处理、产出什么、交给谁。数据任务补上必要的形状、单位、状态、参数来源；社会或经济概念展开条件、选择、代价和反馈，不硬套训练、神经网络或向量。
- 明确哪些量是给定的、测量的、计算的或学习的；说明过程中的改变和保持不变之处。
- 对有多阶段的方法分开讲，例如训练/推理、写入/提交、形成规则/执行决策。区别标签与预测、内部迭代与现实反馈、预测结果与实际执行。
- 需要数学时，先解释符号和假设，再给公式，带第 1 步的数值走过至少一个关键步骤。有迭代就展示两次状态更新或说明停止条件；无数学的概念用一组具体选择完整走通。
- 给出一个可观察的失败位置及如何识别。一个成功样本不证明全局准确、最优或稳健。
- **完成标准**：读者能从起点追到终点，指出每步结果的来源，并解释哪个环节导致结果变化。

### 5. 细节补充：哪些地方还会误解？

- 只补会改变理解或实际应用的 2–4 个问题，优先回答“为什么这样设定”“成立条件”“常见误区”“失效情形”。不另起一套百科。
- 每个问题回接前面某一步，说明它修补哪个简化；把原材料的重要错误用“原说法 → 准确说法 → 影响”简短说明。
- 用一条因果链串起五步，再给一个改变条件的迁移题和简短参考答案。区分“能复述”“能推演”“能迁移”；只有真实作答证据才能判断掌握，生成一篇好文章不代表学生已经学会。
- **完成标准**：关键边界齐备，读者能在变更条件后重新判断，而非只记住故事。

## 连贯与篇幅

- 五步共用同一主样本、变量名、单位和时间约定；切换案例时显式解释对应关系。每节结尾只提出自然引向下一步的问题，不重复整节。
- 默认中文，五个一级标题使用上面的提问形式。完整讲解以约 1500–2500 中文字为起点，按概念复杂度和用户要求调整，避免为凑字数填充。公式用 `$...$` 或 `$$...$$`。
- 用户只追问某一点时，只修补相关步骤；用户要求一句话时给一句话。用户要求逐步互动时每轮推进一步，等待其回答；其余情况一次交付五步，不在每一步强制确认。
- 完整五步讲解遇到多步骤流转、状态变化、层级或容易混淆的关系时，默认至少配一张解释机制的图；用户明确要求 visualization／可视化／画图时必须交付图。简单定义、单点追问、纯文字要求不强制配图。按 [可视化规范与示例](references/visualization.md) 选择图型和呈现方式。
- 图中沿用正文同一组样本、变量、数值与阶段；图不能替代逐步解释。材料含“暂时无法在飞书文档外展示”时，按有证据的文字解释，标注未见原图，避免假称看过。
- 默认直接在对话交付。用户要保存时再写文件；不自动创建长期学习计划、浏览器页面或发布文档。连续多课学习可转给 `teach` 等课程流程，本 skill 只负责单个概念的解释单元。

## 交付前检查

- Toy sample 有实际规则、状态变化与结果；第 4 步确实跑通它。
- 同类关系没有把不同分类轴混排；类比有映射和失效点。
- 公式、数值、输入输出、前后阶段一致；教学数字和实测数字分开。
- 五步没有更换概念含义；重要纠错靠近第一次涉及处。
- 迁移题改变了一个关键条件，参考答案能从前文推出来。
- 应配图的完整讲解已有机制图，箭头标明规则／条件，图文数值一致；只输出画图计划或未执行的工具调用不算交付。
