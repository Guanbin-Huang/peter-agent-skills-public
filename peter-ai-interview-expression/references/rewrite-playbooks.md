# 改写与训练：只用用户的真实工作

先读 [真实工作面试剧本流程](real-work-interview-script.md)。这里提供组织方式，不提供可冒用的预填经历。

## 采集当前问题需要的信息

读取目标岗位/面试问题、真实项目场景、本人角色、关键事件、当时判断、实际动作、结果与现在的复盘。字段缺失时判断是否影响这次表达；关键事实待确认，其余先用现有材料写。不要为完整骨架强制补造项目、指标、失败或迁移。

## 口述骨架

开场：`真实任务与关键问题 → 本人承担的部分 → 关键判断或动作 → 真实结果/现状`。

展开：`当时的约束 → 实际考虑/尝试的方案 → 本人的选择与理由 → 实际动作及变化 → 现在的理解`。

反问：`已知团队问题 → 本人真实关注或相近经验（有则用） → 希望进一步了解的约束/挑战`。

只使用材料中存在的环节。没有数字就讲真实观察、产物或状态；没有成功就说明局部结果和未解决部分；没有复用经历就提炼当前认识，不预填“推广到多个场景”。

## 技术问题：把术语落到真实选择

按本人实际项目选择一个相关问题，不要求背完整技术清单：

| 方向 | 可用于追问的约束 |
|---|---|
| Transformer/Attention | 长度、显存、延迟、吞吐、位置编码或 KV cache；本人具体改过哪一段 |
| SFT/对齐 | 数据覆盖、标注、训练设置、评测分布；证据支持哪种变化 |
| RAG/Agent | 检索粒度、召回/重排、状态、工具参数与任务验收；哪个环节真实失效 |
| 推理优化 | 精度与成本取舍、批处理、量化或并行；实际环境和比较口径 |
| VLA/具身 | 数据契约、动作表示、控制接口、离线/仿真/真机差异；本人负责哪一层 |

这些是提问方向，不是所有系统已经存在的问题，也不自动成为候选人的技术方案。技术结论另查对应版本的一手来源。

## 简历与剧本共用事实

简历条目按 `实际任务 → 本人动作/取舍 → 可说明的结果 → 贡献边界` 压缩；剧本用同一事实展开事件。不得为了符合格式添一个指标变化或“成功上线”。

## 追问与对戏

围绕同一件事问：为什么这是关键问题；本人依据什么判断；有哪些实际替代方案；动作与结果如何连接；如果约束变化，现在会怎么选。改变约束的题是推演，不改过去发生的事实。

候选人回答后，只改被问题暴露的部分：事实冲突回底稿，表达绕圈改顺序，技术空洞查实际代码/资料，岗位关联弱再提炼问题价值。不要给候选人塞一个标准答案让其扮演没做过的工作。

## 自检：不报伪精确分数

检查是否讲清真实任务、个人判断、关键取舍、实际动作、结果口径与岗位关联。结果可以是失败、未完成或定性观察。没有足够材料的维度留空，不以凑齐维度或分数作为通过标准。
