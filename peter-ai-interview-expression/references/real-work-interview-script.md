# 面试剧本杀：源于真实工作，高于真实工作

目的不是复述工作流水账，而是把真实工作里的角色、任务、矛盾、判断、取舍和结果组织成一场可追问的面试。**重组表达，不重写事实。**

## 1. 先找真实工作的戏核

从用户提供的工作记录、项目材料、代码、日志、交付物或本人叙述中找一个值得展开的问题。材料可以零散，先理解，再整理；不要求用户先写成标准答案，也不为补齐结构增加事件。

- **角色卡**：本人、协作方、决策者、验收者分别是谁、承担什么；角色只取自实际工作。没有经理/客户参与记录，就不安排这些角色出场。
- **事件卡**：任务、原始状态、发生顺序、本人动作、实际结果。保留真实时间线与职责，表达时可先讲结果再回到起因，但不能把几件事拼成一件发生过的事。
- **矛盾卡**：工作中真正存在的约束与冲突。没有发生过争执、事故、救火或危机，不为了戏剧性补写。
- **选择卡**：当时的判断、实际考虑或尝试的方案、本人做出的取舍及理由。事后复盘产生的新认识写“现在回看”，不倒写成当时就有的远见。
- **线索卡**：支撑关键事实的记录与本人解释；外部论文/代码只支持机制理解，S 不替代 E。接受明确标记的本人自述，不把每句口述变成审计报告。

结果不是必须成功。失败、局部完成、未上线、未解决也能成为剧本中心，只要能讲清本人做了什么、为什么，以及现有结果说明什么。

## 2. 高于真实工作：提炼，不杜撰

允许调整开场、信息顺序、详略、语言和追问钩子；从具体动作提炼问题类型、判断依据、取舍逻辑和适用边界，让面试官理解工作的价值。

将三层分开保存：

| 层 | 可以写什么 | 不自动推出什么 |
|---|---|---|
| 原始事实 | 用户实际做过、材料实际记录的事情 | 未提供的数字、职级、客户、上线或交付 |
| 当时的判断 | 原记录或本人确认的当时思路与决策 | 事后才想到的解释也是当时的意图 |
| 事后复盘 | 今天能总结的方法、失误与下一次的做法 | 已经在别的项目复用、已经带来额外收益 |

角色有张力不等于编人物原话；有变化不等于硬写反转；工作有价值不等于补一个成功指标。未记录的对话用事实转述，不加引号伪装原话。没有量化结果就讲实际观察、交付物或当前状态；没有复用记录就说“这让我形成了一个判断”，不说“后来推广到多个项目”。

## 3. 从档案到可演练的剧本

1. **选主线**：按当前面试问题与岗位，选择最能展开真实判断的一件事。只要简历 bullet 时提炼同一事实，不强制生成全套文件。
2. **排场次**：开场交代任务与关键问题；中段展开本人判断、动作和取舍；收束说明真实结果与今天的理解。只使用材料中存在的环节。
3. **留钩子**：优先留能展开细节的决策、异常、接口或协作节点，不靠大数字和技术名词装饰。
4. **开追问分支**：围绕同一事件准备角色视角、正序/倒序、替代方案、结果口径与改变约束的问法。假设题是未来推演，不登记成过去经历。
5. **对戏修稿**：候选人用自己的语言回答；追问暴露事实缺口就回材料澄清，暴露表达问题就改结构。事实清楚而表达仍平，不结束在“补证”，继续提炼为什么难、本人判断和岗位价值。

追问不是要求每个项目都发生失败、消融、上线和客户验收。某个环节没有发生，就说没有，并围绕实际发生的部分深挖。没有项目之外的经历，不补成长故事或迁移成果。

## 4. 两份产物共用事实，不共用文风

- **项目学习档案**：保存原始事实、角色/事件/选择、技术机制、来源定位、事后复盘与仍待确认的事项。
- **面试剧本**：给候选人可直接说出口的开场、展开和追问分支。证据编号与缺口清单放附录，不塞满口述正文；关键事实未确认的段落留待确认，不用一句含糊话掩盖。

用户只要一种产物时只交付这一种。时长与钩子数量是排练建议，不是已经录音测得的结果，也不是项目质量标准。

## 5. 交付自检与复用提示词

检查每个具体事件、人物、动作、数字、成果是否来自原材料或明确本人自述；检查当时的判断与事后复盘是否分开；检查是否真的完成了角色、矛盾、取舍、问题价值的提炼，而不是只给材料贴标签。

