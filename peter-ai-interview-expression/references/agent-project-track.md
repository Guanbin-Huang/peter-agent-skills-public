# A｜Agent项目块

## 领域与资料池

对应 `domain=agent`，60公司席位：中国30/美国30。涵盖模型底座、Agent框架/运行时、企业平台与真实业务工程；模型公司不等于所有Agent架构都由它实现。先用筛选器的 `--domain agent` 局部查找，再执行 `official-sources-workflow.md` 的来源卡与C/E/S映射。

## 项目学习档案：围绕一条任务闭环

| 层 | 要厘清的内容 | 要找的证据 |
|---|---|---|
| 场景与本人职责 | 谁想完成什么任务、现有流程、本人参与边界 | 需求、聊天原话、提交、测试与协作记录 |
| 技术链路 | 输入schema→上下文/检索→规划或状态→工具参数→调用结果→任务结果 | 入口、数据流、状态持有位置、代码/版本与输出 |
| 可靠性与评估 | 超时、重试、幂等、权限、记忆读写；用户任务成功而不只是HTTP状态 | 最小复现、对照测试、失败例、端到端判据与运行记录 |
| 非技术取舍 | 价值、时间/成本、协作者与决策、上线/验收、遗留问题 | 实际约束与交付记录；官方案例只提供思路，不替代自身证据 |

不要强制给每个项目加记忆、多Agent、MCP等全部关键词。选择与本人实际动作和目标岗位相关的主线；仅了解的机制进入学习区。

## 逐字稿展开

`用户任务与痛点 → 我的具体职责 → 一个真实判断/取舍 → 工具/状态/评估的关键动作 → 实际任务结果 → 局限与可追问点`

开场只暴露1–2个证据充分的钩子；深挖按异常、候选原因、检查、修改、回归展开。阅读官方案例时用调研表达；本人做过且有E才用实现/修复表达。接口HTTP 200、模型答得流畅、工具返回success均不自动代表业务成功。

## 验收

资料筛选明确 `domain=agent`；来源卡说明适用版本；项目数据流/本人边界清楚；技术与非技术证据分别落点；真实贡献、仅学习和待验证分开。机器人动作、相机标定与真机指标不因为“Agent也要执行”就复制进本块。
